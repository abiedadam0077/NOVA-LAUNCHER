## 1. دراسة المنافسين

### أ. محركات تشغيل Minecraft Java على Android
| المشروع | النجوم | الترخيص | اللغة | الحالة |
|---|---|---|---|---|
| PojavLauncherTeam/PojavLauncher | 9.4k | LGPL-3.0 | Java/C | مُخلَّف لصالح Amethyst |
| AngelAuraMC/Amethyst-Android | 2.3k | LGPL-3.0 | C/Java | الخلف النشط لـ Pojav (فرع v3_openjdk) |
| FCL-Team/FoldCraftLauncher | 4.9k | GPL-3.0 | Java | نشط |
| ZalithLauncher/ZalithLauncher2 | 2.0k | GPL-3.0 | Kotlin | نشط، واجهة Compose |
| AOF-Dev/MCinaBox | 1.3k | GPL | Java | قديم |

**الخلاصة التقنية:** كل هذه المشاريع تشغّل Minecraft Java عبر نفس المبدأ:
1. **JRE حقيقي مُحوَّل (cross-compiled) لأنظمة Android** (OpenJDK مع دعم AWT مخصص).
2. **طبقة LWJGL shim** (كلاسات `org.lwjgl.glfw.GLFW` و`CallbackBridge` تربط إدخال اللمس بلوحة مفاتيح/ماوس افتراضية).
3. **مترجمات رسوميات**: زاوية (ANGLE → OpenGL ES)، VirGL، أو gl4es لترجمة أوامر OpenGL القديمة.
4. **مكونات مساعدة**: caciocavallo (AWT sandbox)، forge_installer agent، log4j RCE patches.
5. ملفات الأصول (assets) والمكتبات تُنزَّل من خوادم Mojang الرسمية (نفس مصادر اللانشر الرسمي).

**ما درسناه من تجربة المستخدم لديها:**
- الصفحة الرئيسية: زر تشغيل كبير + اختيار إصدار + معلومات الحساب (نفس البنية التي تعتمدها مواصفاتنا).
- تثبيت الإصدارات: قوائم مع حالة تنزيل لكل ملف وإعادة محاولة.
- إعدادات Java: تخصيص RAM بحدود آمنة + JVM arguments.
- إدارة المودات: مجلد mods لكل نسخة + فحص التوافق.
- معالجة أخطاء التشغيل: التقاط stdout/stderr من عملية JVM + تحليل الـ crash.
- الأداء على الأجهزة الضعيفة: تقليل دقة العرض، تخصيص معالجات رسوميات بديلة.

### ب. اللانشرات المكتبية (أفكار إدارة)
- **اللانشر الرسمي / Prism Launcher**: بنية ملفات قياسية `.minecraft` (versions/، libraries/، assets/objects/، launcher_profiles.json) — سنعتمد نفس البنية حرفياً لضمان التوافق.
- **مصادر بيانات الإصدارات الرسمية:**
  - `https://piston-meta.mojang.com/mc/game/version_manifest_v2.json` — فهرس كل الإصدارات مع روابط وSHA1.
  - `https://resources.download.minecraft.net/{2 أول حرفين من الهاش}/{الهاش}` — أصول اللعبة.
  - `https://meta.fabricmc.net/v2/...` — بيانات Fabric (عامة دون مفتاح).
  - `https://files.minecraftforge.net/net/minecraftforge/forge/promotions_slim.json` — إصدارات Forge.
  - Modrinth API `https://api.modrinth.com/v2/...` — كتالوج مودات/حزم موارد/ظلال/مودباكات (عام دون مفتاح، يسمح بإعادة التوزيع وفق تراخيص المحتوى).

### ج. قرارات التصميم المستلهمة (دون نسخ)
- شريط تنقل سفلي عائم بحواف دائرية (شائع في تطبيقات Gaming الحديثة) — تنفيذه أصلي بالكامل.
- بطاقات زجاجية داكنة بتوهج خفيف للأزرار الأساسية فقط.
- فصل "المحتوى" في تبويبات (مودات/خرائط/موارد/مودباكات) بدل تكديسها في شاشة واحدة.

## 2. البحث التقني — كيف يعمل Minecraft Java على Android؟

**الحقيقة الجوهرية:** Flutter وحده لا يستطيع تشغيل Minecraft Java. اللعبة تحتاج:
- JVM كامل (وليس ART/Dalvik) لأن اللعبة تعتمد على مكتبات لا تعمل على ART.
- LWJGL 3 (OpenGL/OpenAL/GLFW) — غير موجود على Android، يحتاج طبقات ترجمة.
- إدخال لوحة مفاتيح/ماوس مُحاكى.

لذلك بنية التشغيل الوحيدة الواقعية هي: **محرك تشغيل أصلي (Native Runtime)** — وهذا ما توفره المشاريع أعلاه.

### قرار التكامل المعتمد في NOVA (طبقة RuntimeBridge)
1. **NOVA يجهّز بيئة لعبة كاملة وقياسية**: تنزيل الإصدار + المكتبات + الأصول من خوادم Mojang الرسمية مع تحقق SHA1، بنفس بنية `.minecraft`.
2. **محرك التنفيذ** له وضعان:
   - **وضع الجسر إلى Runtime مثبّت** (الوضع الأساسي الفعّال اليوم): إذا كان على الجهاز runtime متوافق (Amethyst/PojavLauncher/Zalith/FCL) فإن NOVA يسلمه النسخة المُعدَّة ويشغّلها. كما يدعم تنزيل وتثبيت آخر إصدار من runtime مفتوح المصدر بموافقة المستخدم.
   - **وضع الدمج الكامل** (سقالة جاهزة): وحدة `nova_runtime` مُعدَّة لدمج مشروع Amethyst-Android (LGPL-3.0) كوحدة Gradle. التنفيذ الكامل يتطلب سلاسل أدوات NDK + أصول JRE (~200MB) الخاصة بهم، وهي مذكورة في `docs/EMBEDDING_RUNTIME.md`. **الحالة: سقالة + توثيق — ليس منفذاً بالكامل بعد** (راجع تقرير الحالة النهائي).
3. هذا القرار يحترم التراخيص (لا نسخ كود مخالف)، ولا يعيد اختراع طبقات C معقدة، ويُبقي كل وظائف الإدارة (إصدارات/مودات/سيرفرات/حسابات) أصلية داخل NOVA.

### المصادقة
- تدفق **Microsoft Device Code** الرسمي (بدون إدخال كلمة مرور داخل التطبيق): `login.microsoftonline.com/consumers/oauth2/v2.0/devicecode` ثم تبادل الجهاز → رموز Xbox Live → XSTS → Minecraft.
- **قيد صريح:** الوصول لواجهة "المصادقة الكاملة" يتطلب تسجيل تطبيق Azure ببيان تصريح رسمي من طرف المستخدم/المالك. نوفّر خانة Client ID قابلة للتخصيص ونوثّق الخطوات، ونوفّر **ملفات تعريف محلية (Offline)** لإدارة التطبيق والعب المحلي دون مصادقة. (البرومبت نفسه يفصل بين Local Profile وMicrosoft Account).

### متطلبات الإصدارات
- الإصدارات الحديثة (1.18+) تحتاج Java 17+، و1.20.5+ تحتاج Java 21 — يحددها حقل `javaVersion.majorVersion` في JSON الرسمي. نوفّر اختيار runtime مناسب لكل نسخة.
- الإصدارات القديمة (قبل 1.13 تقريباً) تعمل بـ Java 8.
- Shaders تتطلب OpenGL ≥ 3.2/4.6 حسب الحزمة عبر طبقات الترجمة — لا نعد بدعم شامل.

## 3. أفضل بنية تقنية

```
lib/
├── core/            ثيم، حركة، تعريب، توجيه، ثوابت
├── data/            HTTP، Piston، Fabric، Modrinth، Microsoft، تنزيلات، NBT، قواعد بيانات
├── domain/          نماذج + خدمات (إصدارات، مودات، موارد، خرائط، حسابات، سيرفرات، أداء، جسر التشغيل)
└── presentation/    شاشات + ويدجت (طبقة العرض فقط)
android/             Kotlin: قنوات منصة (معلومات جهاز، ملفات، جسر runtime)
```
- **الحالة:** Riverpod. **التنقل:** GoRouter. **التخزين:** SQLite عبر sqflite + flutter_secure_storage للحساس. **لا WebView إطلاقاً.**

## 4. المكتبات المعتمدة (الحد الأدنى)
flutter_riverpod، go_router، http، crypto، archive، sqflite، path_provider، path،
flutter_secure_storage، file_picker، url_launcher، shared_preferences، intl.

## 5. خطة تشغيل Minecraft
1. جلب فهرس الإصدارات الرسمي → اختيار نسخة.
2. تنزيل: عميل اللعبة + المكتبات + فهرس الأصول + كائنات الأصول (تحقق SHA1 لكل ملف، استئناف عبر Range، إعادة محاولة).
3. كتابة ملفات النسخة + `options.txt` حسب بروفايل الأداء + مزامنة `servers.dat` (كاتب NBT أصلي داخل التطبيق).
4. التشغيل عبر RuntimeBridge (انظر القسم 2 أعلاه).

## 6. خطة المودات
- كتالوج خارجي عبر **Modrinth API** (search + versions + روابط مباشرة بموافقة المستخدم لكل تنزيل + عرض المصدر والترخيص).
- استيراد من الهاتف (`.jar`)، فحص التوافق عبر حقول النسخة في بيانات المشروع، كشف التكرار، نسخ احتياطي قبل التغييرات.
- زر **OPTIMIZE MY GAME**: يفحص النسخة/المحمل/الجهاز ويقترح (مثل Sodium+Lithium+FerriteCore...) بعرض ملخص وموافقة وتراجع.

## 7. خطة الأداء
- قراءة قانونية لمواصفات الجهاز عبر قناة منصة (ActivityManager/StatFs/Build/proc) — دون تخمين.
- بروفايلات: LITE / BALANCED / PERFORMANCE / VISUAL / CUSTOM تكتب `options.txt` فعلياً (مسافة عرض، جزيئات، رسوميات...).
- لا وعود بأرقام FPS.

## 8. المخاطر التقنية
| الخطر | الأثر | التخفيف |
|---|---|---|
| تعذّر اختبار تشغيل اللعبة فعلياً (لا يوجد جهاز في بيئة العمل) | عالٍ | تسليم بنية تشغيل حقيقية + توثيق صريح في تقرير الحالة |
| مصادقة Microsoft تحتاج تسجيل Azure | متوسط | تدفق جهاز كامل جاهز + خانة Client ID + ملفات محلية |
| صيغ Forge/NeoForge/Quilt تحتاج تشغيل مثبّت JAR | متوسط | Fabric كامل الآن؛ عرض/تنزيل للبقية مع وسم حالة |
| ثقل أصول runtime (~200MB) عند الدمج الكامل | متوسط | وضع الجسر كحل أساسي + توثيق الدمج |

## 9. خطة الاختبار
- وحدة: كاتب NBT، محلل Piston، مقارنة إصدارات، مدير التنزيلات (عميل HTTP وهمي)، مزامنة السيرفرات، بروفايلات الأداء.
- ويدجت: آلة حالة زر التشغيل، التنقل، RTL.
- CI: `flutter analyze` + `flutter test` + بناء Debug وRelease على GitHub Actions (مجاني، دون VPS).
- اختبار اللعبة على جهاز حقيقي: **غير متاح في بيئة العمل — يُصرَّح بذلك في التقرير النهائي.**

## 10. طريقة بناء APK
- محلياً: غير ممكنة في بيئة العمل الحالية (لا توجد أدوات JDK/Android SDK/Flutter ولا يمكن تنزيلها من مصادر خارج النطاق المسموح).
- **المعتمد:** GitHub Actions — workflow يثبّت Flutter، يشغّل التحليل والاختبارات، يبني `app-release.apk` موقّعاً بمفتاح إنشاء لحظي داخل بيئة التشغيل (لا يُخزَّن أي سر في المستودع)، وينشره كـ Release برابط تنزيل مباشر.
